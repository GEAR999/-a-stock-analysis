# 李富贵推送系统对接文档

## 概述

本文档描述 A 股智能分析系统与李富贵推送系统的对接规范，包括数据格式、接口协议、认证方式等。

---

## 1. 推送接口

### 1.1 接口信息

| 项目 | 值 |
|------|-----|
| **URL** | `POST https://a-stock.xyz/api/multifactor` |
| **认证** | Bearer Token（`Authorization: Bearer <PUSH_TOKEN>`） |
| **Content-Type** | `application/json` |
| **推送频率** | 建议每 5 ~ 10 分钟推送一次（交易时段） |

### 1.2 请求体格式

```json
{
  "total_volume": 12500,
  "volume_change_pct": 5.2,
  "turnover_rate": 2.85,
  "turnover_change_pct": 0.3,
  "limit_up_count": 85,
  "limit_up_change_pct": 12.5,
  "limit_down_count": 12,
  "limit_down_change_pct": -20.0,
  "margin_balance": 18500,
  "margin_change_pct": 0.15
}
```

### 1.3 字段说明

| 字段名 | 类型 | 必填 | 说明 | 对应因子 |
|--------|------|------|------|----------|
| `total_volume` | number | 是 | 两市成交额（亿元） | M1 |
| `volume_change_pct` | number | 否 | 成交额变化率（%） | M1 |
| `turnover_rate` | number | 否 | 换手率（%） | M2 |
| `turnover_change_pct` | number | 否 | 换手率变化率（%） | M2 |
| `limit_up_count` | number | 是 | 涨停数（家） | M3 |
| `limit_up_change_pct` | number | 否 | 涨停数变化率（%） | M3 |
| `limit_down_count` | number | 是 | 跌停数（家） | M4 |
| `limit_down_change_pct` | number | 否 | 跌停数变化率（%） | M4 |
| `margin_balance` | number | 否 | 融资余额（亿元） | M5 |
| `margin_change_pct` | number | 否 | 融资余额变化率（%） | M5 |

### 1.4 字段缺失处理

系统具备**自动补齐**能力，推送方可以只推送核心字段：

| 缺失字段 | 补齐方式 |
|----------|----------|
| `turnover_rate` | 从 Tushare 获取全市场换手率（缓存 10 分钟） |
| `margin_balance` | 从 Tushare 获取沪深融资余额合计（缓存 10 分钟） |
| `*_change_pct` | 与上一条推送快照对比自动计算 |

**建议推送策略**：
- **必须推送**：`total_volume`、`limit_up_count`、`limit_down_count`
- **建议推送**：所有 `change_pct` 字段（避免依赖历史快照计算）
- **可选推送**：`turnover_rate`、`margin_balance`（系统会自动补齐）

## 2. 认证方式

### 2.1 Bearer Token

推送请求必须在 Header 中携带 Bearer Token：

```
Authorization: Bearer <PUSH_TOKEN>
```

### 2.2 Token 获取

Token 由系统管理员配置在环境变量 `PUSH_TOKEN` 中。

**获取方式**：联系系统管理员获取当前有效的 PUSH_TOKEN。

### 2.3 认证失败响应

```json
{
  "success": false,
  "error": "未授权访问"
}
```

HTTP 状态码：`401`

## 4. 情绪评分算法

### 4.1 因子评分公式

每个因子评分 = **水位分 × 0.6** + **趋势分 × 0.4**

| 组成部分 | 说明 | 取值范围 |
|----------|------|----------|
| 水位分 | 当前值在历史区间中的位置 | -5 ~ +5 |
| 趋势分 | 变化率反映的趋势方向 | -5 ~ +5 |

### 4.2 综合评分

综合评分 = 所有可用因子评分的平均值

**注意**：如果某个因子数据缺失，该因子不参与平均分计算。

### 4.3 热度等级映射

| 评分区间 | 热度等级 |
|----------|----------|
| +4 ~ +5 | 极度狂热 |
| +3 ~ +4 | 强烈过热 |
| +2 ~ +3 | 过热 |
| +1 ~ +2 | 偏热 |
| 0 ~ +1 | 温和偏热 |
| 0 | 中性 |
| 0 ~ -1 | 温和偏冷 |
| -1 ~ -2 | 偏冷 |
| -2 ~ -3 | 冷淡 |
| -3 ~ -4 | 强烈冷淡 |
| -4 ~ -5 | 极度冰点 |

## 5. 数据存储

### 5.1 数据表

推送数据保存到 `sentiment_snapshot` 表：

```sql
CREATE TABLE sentiment_snapshot (
  id SERIAL PRIMARY KEY,
  timestamp TIMESTAMP DEFAULT NOW(),
  total_volume DECIMAL,
  volume_change_pct DECIMAL,
  turnover_rate DECIMAL,
  turnover_change_pct DECIMAL,
  limit_up_count INTEGER,
  limit_up_change_pct DECIMAL,
  limit_down_count INTEGER,
  limit_down_change_pct DECIMAL,
  margin_balance DECIMAL,
  margin_change_pct DECIMAL,
  sentiment_score DECIMAL,
  heat_level VARCHAR(50),
  factor_scores JSONB,
  raw_data JSONB
);
```

### 5.2 数据用途

| 用途 | 说明 |
|------|------|
| 多因子面板 | 实时显示大盘情绪热度 |
| 仓位计算 | 根据情绪评分调整建议仓位 |
| 历史回溯 | 分析情绪与行情的关系 |

## 6. 推送示例

### 6.1 cURL 示例

```bash
curl -X POST https://a-stock.xyz/api/multifactor \
  -H "Authorization: Bearer YOUR_PUSH_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "total_volume": 12500,
    "volume_change_pct": 5.2,
    "limit_up_count": 85,
    "limit_up_change_pct": 12.5,
    "limit_down_count": 12,
    "limit_down_change_pct": -20.0
  }'
```

### 6.2 Python 示例

```python
import requests
import json

PUSH_URL = "https://a-stock.xyz/api/multifactor"
PUSH_TOKEN = "YOUR_PUSH_TOKEN"

def push_sentiment(data: dict):
    """推送情绪数据"""
    headers = {
        "Authorization": f"Bearer {PUSH_TOKEN}",
        "Content-Type": "application/json"
    }
    
    response = requests.post(PUSH_URL, headers=headers, json=data)
    
    if response.status_code == 200:
        result = response.json()
        if result.get("success"):
            print(f"推送成功，情绪评分：{result['data']['totalScore']}")
            print(f"热度等级：{result['data']['heatLevel']}")
        else:
            print(f"推送失败：{result.get('error')}")
    else:
        print(f"HTTP 错误：{response.status_code}")

# 示例数据
sentiment_data = {
    "total_volume": 12500,
    "volume_change_pct": 5.2,
    "limit_up_count": 85,
    "limit_up_change_pct": 12.5,
    "limit_down_count": 12,
    "limit_down_change_pct": -20.0
}

push_sentiment(sentiment_data)
```

### 6.3 Node.js 示例

```javascript
const PUSH_URL = "https://a-stock.xyz/api/multifactor";
const PUSH_TOKEN = "YOUR_PUSH_TOKEN";

async function pushSentiment(data) {
  const response = await fetch(PUSH_URL, {
    method: "POST",
    headers: {
      "Authorization": `Bearer ${PUSH_TOKEN}`,
      "Content-Type": "application/json",

  if (result.success) {

    console.log(`热度等级：${result.data.heatLevel}`);
  } else {
    console.error(`推送失败：${result.error}`);
  }
}

// 示例数据
const sentimentData = {
  total_volume: 12500,
  volume_change_pct: 5.2,
  limit_up_count: 85,
  limit_up_change_pct: 12.5,
  limit_down_count: 12,
  limit_down_change_pct: -20.0,
};

pushSentiment(sentimentData);
```

## 7. 最佳实践

### 7.1 推送频率

| 场景 | 建议频率 | 说明 |
|------|----------|------|
| 交易时段（9:30-11:30, 13:00-15:00） | **每 5 ~ 10 分钟** | 情绪数据变化较慢，无需高频推送 |
| 开盘/收盘前后 30 分钟 | 每 3 ~ 5 分钟 | 波动较大时可适当提高频率 |
| 非交易时段 | 无需推送 | - |
| 休市日 | 无需推送 | - |

**注意**：过于频繁的推送（如每秒一次）会增加服务器和数据库负载，且用户端感知不明显。

### 7.2 数据准确性

- **成交额**：使用实时累计成交额，非预测值
- **涨停/跌停数**：包含 ST 股票
- **变化率**：与前一交易日同一时刻对比（非与前一日收盘对比）

### 7.3 错误处理

- 推送失败时**不要重试**（避免重复数据）
- 记录失败日志，下次推送时携带最新数据即可
- 系统会自动处理数据缺失情况

### 7.4 网络要求

- 使用 HTTPS 协议
- 确保服务器 IP 未被防火墙拦截
- 建议设置合理的超时时间（5-10 秒）

## 8. 常见问题

### Q1: 推送频率有限制吗？

**A**: 没有硬性限制，但建议每 30 秒 ~ 1 分钟推送一次。过于频繁的推送（如每秒一次）会增加服务器负载。

### Q2: 必须推送所有字段吗？

**A**: 不需要。系统会自动补齐缺失字段：
- `turnover_rate` 和 `margin_balance` 会从 Tushare 自动获取
- `change_pct` 字段会与历史快照对比计算

### Q3: Token 泄露了怎么办？

**A**: 联系系统管理员重置 `PUSH_TOKEN` 环境变量，旧 Token 会立即失效。

### Q4: 推送的数据会公开吗？

**A**: 不会。推送数据仅用于系统内部计算，不会对外暴露。

### Q5: 如何验证推送是否成功？

**A**: 检查响应中的 `success` 字段：
- `success: true` 表示推送成功
- `success: false` 表示推送失败，查看 `error` 字段了解原因
